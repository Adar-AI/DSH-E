## 2. 技术选型与理由

| 层 | 选型 | 版本基线 | 理由 |
|---|---|---|---|
| 编排 | LangGraph | 1.2.6 | 需要显式状态图（图片分支、命中判断、兜底、工单抽取），且自带 checkpointer 做多轮记忆 |
| Web | FastAPI + uvicorn | 0.141 / 0.52 | 原生支持 multipart 图片上传、SSE 流式、静态托管，一个进程搞定前后端 |
| 存储 | SQLite + FTS5 + sqlite-vec | Python 内置 / 0.1.9 | 单文件零部署；向量与业务数据同库同事务，无需引入 Chroma/FAISS |
| 嵌入 | 本地 BGE-M3（1024 维） | 本机已存在 | 中文检索效果好、完全离线、无 API 成本；默认 CPU 推理以省显存 |
| 对话 | Ollama `qwen3:4b`（默认）+ DeepSeek API（备用） | — | 默认离线私有；备用通道保证演示不中断 |
| 视觉 | OpenAI 兼容多模态网关 | — | 需要看懂报错截图与实物照片 |
| 前端 | 原生 HTML/CSS/JS | — | 零构建、启动即用、样式精确可控 |
| 测试 | pytest（+ 现有 Node 文档校验） | — | 核心逻辑离线可测，模型调用打桩 |

## 4. 数据模型

```sql
-- 知识库
documents(id INTEGER PK, filename TEXT, sha256 TEXT UNIQUE, mime TEXT,
          page_count INT, chunk_count INT, status TEXT, uploaded_at TEXT)
chunks(id INTEGER PK, doc_id INT REFERENCES documents(id) ON DELETE CASCADE,
       ordinal INT, section TEXT, page INT, text TEXT, char_len INT)
chunks_fts   -- FTS5(chunks.text)，external content 指向 chunks
vec_chunks   -- sqlite-vec: vec0(chunk_id INT PK, embedding FLOAT[1024])

-- 会话
conversations(id TEXT PK, session_id TEXT, title TEXT, status TEXT,
              ticket_draft_json TEXT, created_at TEXT, updated_at TEXT)
messages(id INTEGER PK, conv_id TEXT REFERENCES conversations(id) ON DELETE CASCADE,
         role TEXT, text TEXT, image_path TEXT, vision_json TEXT,
         citations_json TEXT, trace_json TEXT, created_at TEXT)

-- 工单
tickets(id INTEGER PK, ticket_no TEXT UNIQUE, conv_id TEXT,
        customer_request TEXT, product_model TEXT, fault_phenomenon TEXT,
        error_info TEXT, tried_actions TEXT, urgency TEXT, suggestion TEXT,
        citations_json TEXT, status TEXT, source TEXT,
        created_at TEXT, updated_at TEXT)
ticket_events(id INTEGER PK, ticket_id INT, from_status TEXT, to_status TEXT,
              note TEXT, created_at TEXT)

-- 多轮记忆（LangGraph SqliteSaver 自建表，由 langgraph-checkpoint-sqlite 管理）
```

约定：状态流转只允许 `待处理 → 处理中 → 已解决 → 已关闭`（允许回退到「处理中」），每次流转写一条 `ticket_events`。

## 5. 检索设计

1. **解析**：PDF 逐页取文本（保留页码）；MD 按标题层级切分并记录章节路径。
2. **分块**：目标 300–500 字，优先在段落/标题边界断开，块间保留 1 句重叠；每块记录 `doc_id / section / page / ordinal`。
3. **嵌入**：BGE-M3 输出 1024 维向量，L2 归一化后写入 `vec_chunks`；模型不可用时置「仅关键词」模式。
4. **召回**：两路并行——
   - 关键词路：FTS5/BM25，查询串做中文切分与转义；
   - 向量路：sqlite-vec KNN 取 Top-N。
5. **融合**：RRF（Reciprocal Rank Fusion）合并两路排名，得到统一打分。
6. **阈值**：融合分低于阈值 → 判定未命中，走兜底话术（对应 F5 验收）。
7. **返回**：Top-K（默认 4）片段，附文档名、页码、分数，供生成与页面展示。

## 5.1 打分公式与阈值标定

三路信号归一后加权求和（缺哪个通道该项为 0）：

```
score = 0.45 · 覆盖率 + 0.35 · 向量相似度 + 0.20 · RRF 排名分
```

- **覆盖率** = 问题 token 在片段里出现的比例（中文二元切分后统计）；
- **向量相似度** = 归一化向量的余弦，再按 `[0.35, 0.85]` 线性拉伸 —— BGE-M3 对不相关
  文本也会给出 0.35~0.45 的相似度，不设地板会把无关片段抬得过高；
- **RRF** = `1/(60+rank)` 两路求和后按通道数归一。

**标定实测**（真实 BGE-M3 + 2 份中文资料，2026-10-12）：

| 问题 | 最高分 | 判定 |
|---|---|---|
| 硒鼓怎么更换 | 0.670 | 命中 ✅ |
| 打印机显示 E05 是什么意思 | 0.500 | 命中 ✅ |
| 保修期是多久 | 0.627 | 命中 ✅ |
| 无线网络连不上怎么办 | 0.648 | 命中 ✅ |
| 预订国际航班机票价格 | 0.247 | 未命中 → 兜底 ✅ |
| 今天北京天气怎么样 | 0.208 | 未命中 → 兜底 ✅ |

命中类 0.50~0.67 与未命中类 0.21~0.25 之间有明显间隔，因此阈值默认取 **0.35**。
若换成别的嵌入模型或语料风格差异大，用 `scripts/calibrate.py` 重跑一遍再调
`RETRIEVE_MIN_SCORE`。

## 6. LangGraph 图设计

**State 关键字段**：`messages`、`current_text`、`image_path`、`vision_result`、`query`、`retrieved`、`hit`、`answer`、`citations`、`ticket_draft`、`mode`（`ollama`/`fallback`/`keyword_only`）。

```
START → prepare ──有图片──→ vision_understand ─→ rewrite_query
             └──无图片──────────────────────────→ rewrite_query
rewrite_query → hybrid_retrieve → judge_hit ──命中──→ generate_answer → update_draft → END
                                            └─未命中─→ fallback_answer ─→ update_draft → END
```

- **记忆**：`thread_id = conversation_id`，checkpointer 持久化到 SQLite，刷新页面/重启服务后上下文仍在（F1）。
- **每轮重置**：`prepare` 节点会清空本轮的图片描述、检索结果、回答与引用，只有工单草稿跨轮保留——
  否则上一轮上传的图片信息会串进这一轮的检索（有专门的回归测试守着）。
- **兜底确定性**：未命中知识库时**不调用模型**，直接输出模板话术（`FALLBACK_USE_MODEL=false`）。
  兜底本身就是"不许编"的场景，交给模型润色反而可能把「内部资料未收录」改写成模糊说法，
  实测还出现过编造无关建议的情况；确定性输出同时保证模型全挂时这条路依然可用。
- **工单草稿**：`update_draft` 每轮增量合并已抽取字段，右侧栏实时展示（F7）。
- **结束会话**：`POST /api/conversations/{id}/close` 触发 `tickets/extractor.py` 定稿，写入 `tickets` 并返回工单号。

### 6.1 工单抽取的可靠性设计

定稿时字段来自两路，**模型结果为主体、规则草稿补空缺**（`merge_draft(模型字段, 规则草稿)`）：

| 层 | 作用 | 失效时的行为 |
|---|---|---|
| ① 结构化提示词 | 固定 JSON 结构，要求单行字段值、建议用一两句话概括 | — |
| ② 解析与校验 | `parse_json_block` 容忍围栏/前后废话/**字符串里的真实换行**；Pydantic 校验并规范化（列表转文本、紧急程度纠偏） | 解析或校验失败 → **重试一次**并强调"只输出 JSON" |
| ③ 规则草稿兜底 | 正则抓型号与报错码、关键词判断紧急程度与已尝试操作 | 两次都失败或模型不可用 → 用规则草稿落库，并把失败原因写进工单事件备注 |

实测教训（已固化为测试）：本地 qwen2.5 会把整段回答塞进 `suggestion` 并**带真实换行**，
标准 `json.loads` 会判定为非法 JSON，导致抽取回退、白等 40 秒。
现在解析用 `strict=False` 放宽控制字符，字段值再压成单行，抽取成功率与耗时都恢复正常
（21.9s → 11.3s）。

状态机的合法流转定义在 `app/tickets/service.py` 的 `ALLOWED_TRANSITIONS`，
非法流转一律 400 + 说明。删除会话不会删除工单（工单是留档记录）。

## 7. LLM 接入与降级

| 能力 | 首选 | 备用 | 降级行为 |
|---|---|---|---|
| 对话/抽取 | 本地 Ollama（`qwen2.5:latest`） | DeepSeek API（可关） | 首选失败自动切备用，`mode` 标记并在页面提示 |
| 图片理解 | **本地 Ollama 视觉模型**（`qwen2.5vl:3b`） | 云端网关（`qwen3.5-omni-plus`，可关） | 本地模型未拉取/加载失败 → 自动回退云端，并在结果里标明实际通道 |
| 嵌入 | 本地 BGE-M3 | 无 | 置「仅关键词」模式，检索退化为 FTS5 |
| 离线开发 | `LLM_MODE=mock` | — | 对话与视觉换成确定性假模型，不联网、不需要 Key，用于先跑通后端逻辑 |

统一接口：所有通道都实现 `chat(messages, **kw) -> str`、`chat_stream()`、`available()`、`ping()`，
由 `ChatChain` 串成「首选 → 备用」的降级链，便于注入假客户端做离线测试。

### 7.1 通道实测记录（2026-10-12，RTX 3060 Laptop 6GB）

| 通道 | 模型 | 结果 | 实测延迟 | 结论 |
|---|---|---|---|---|
| 本地 Ollama | `qwen2.5:latest`（7.6B） | ✅ 可用 | 冷启动 72.6s / **预热后 7.2s** | **选为默认**；4.77GB 权重中 3.9GB 入显存，冷启动代价大，服务启动时预热 |
| 本地 Ollama | `qwen3:4b` | ⚠️ 正文为空 | 26.9s | 思考型模型把 token 预算花在推理上；需 `/no_think` 才能用，不设为默认 |
| 备用通道 | `deepseek-chat` | ✅ 连通 | — | 云端通道，Ollama 未启动/无模型时自动接管 |
| 多模态 | `qwen3.5-omni-plus` | ✅ 可用 | — | 网关共 175 个模型；测试图正确读出 `ERROR E05`、`Drum unit not detected`、`Model: L3250` |

回答实测（带 2 条资料片段）正确产出了引用标注：

```
1. 请先检查硒鼓芯片触点是否清洁。根据资料片段 [1]……
2. 如果清洁后问题依旧，请联系售后服务中心进行进一步检查。[2]
```

**工程结论**：① 默认模型用 `qwen2.5:latest`；② 服务启动时后台预热对话模型与嵌入模型，
把冷启动时间从用户请求里挪走；③ 页面用流式输出，首包即可见，弱化整段等待感。

自检命令：`scripts/probe_chat.py`（对话通道 + 延迟）、`scripts/probe_vision.py`（多模态链路）。

### 7.2 模型层作用实测对照（2026-10-12）

同一套后端代码、同一批演示资料、同一个冒烟脚本，只切换 `LLM_MODE`，结果如下：

| 维度 | `LLM_MODE=mock`（离线） | `LLM_MODE=auto`（真实模型） |
|---|---|---|
| 文字回答 | 固定模板 + 首条资料摘要，显式标注「离线模式·未调用大模型」 | 9.7s 出稿、222 个流式增量；按资料分步作答并标注 `[1][2][3][4]`，能结合"刚换过硒鼓"追问保修与更换流程 |
| 图片理解 | 占位描述，置信度 0，明确说明未真正识别 | 8.6s 识别出**型号 L3250、错误码 E05、英文提示 `Drum unit not detected`，置信度 1.0** |
| 图片信息进入后续链路 | 无（无错误码可带入） | 自动补进检索查询，工单草稿型号由空变为 `L3250` |
| 工单定稿 | 来源 `llm`（走假模型），填充 **5/6**，型号为空 | 来源 `llm`，填充 **6/6**，型号 `L3250` |
| 检索命中 | 命中（最高分 0.64~0.69，向量走真实 BGE-M3） | 命中（最高分 0.48~0.64） |
| 兜底链路 | 确定性模板，不经模型 | 完全相同（设计如此，避免模型改写"未收录"表述） |
| 后端冒烟 15 项 | 15/15 通过 | 15/15 通过 |
| 外部依赖 | 无网络、无 Key、不需要 Ollama | Ollama `qwen2.5:latest` + 多模态网关（DeepSeek 备用） |

结论：**后端逻辑与模型层解耦**——离线模式足以验证接口、状态机、落库与导出；
换成真实模型后，多出来的是「理解能力」：语义归纳、图片识别、字段补全与可直接交付客户的成稿质量。
演示建议：先用 mock 模式确认流程，再用 auto 模式展示真实效果。

### 7.3 本地视觉模型接入实测（2026-10-12）

视觉通道支持本地 Ollama 与云端网关两种后端，**`VISION_*` 配置优先，留空回落到旧名 `QWEN_*`**，
本地地址自动视为"不需要 API Key"，并在本地为主通道时按 `VISION_AUTO_CLOUD_FALLBACK` 自动挂上云端回退。

| 实测项 | 结果 |
|---|---|
| 通道链（`/api/health`） | `vision-local`（`qwen2.5vl:3b`，本地 Ollama，无需密钥）→ `vision-cloud-fallback`（`qwen3.5-omni-plus`） |
| 识别质量（本地 3B） | 正确读出「型号 L3250 / 错误码 E05 / 报错位置 屏幕顶部 / 鼓单元未检测到」，置信度 0.9；工单草稿自动补上型号 |
| **纯视觉推理** | **8.5s**（560×260 截图，模型已在显存） |
| 一次完整图片问答 | **34.6s** —— 因为 6GB 显存装不下两个模型，流程里有**两次换页**：文本模型卸载 → 载入视觉模型识别 → 再换回文本模型生成回答 |
| 文字问答（热态 / 冷启动） | 4.9s / 27.6s |
| 显存驻留 | `qwen2.5:latest` 占 3.90GB（权重 4.77GB，余量落 CPU）；`ollama ps` 确认两个模型不会同时常驻 |
| 回退验证 | 故意把本地模型名写错 → 4.7s 内自动切到云端通道并成功识别（`provider=vision-cloud-fallback`） |

**工程取舍建议**（按 6GB 显存）：

| 取向 | 做法 | 代价 |
|---|---|---|
| 全本地 + 识别质量 | 文本 `qwen2.5:latest` + 视觉 `qwen2.5vl:3b`（当前配置） | 每张图 ~35s（含两次换页） |
| 全本地 + 少换页 | 文本与视觉都用 `gemma3:4b`（单模型双模态，3.1GB） | 中文文本质量弱于 Qwen 7B |
| 全本地 + 小模型 | 视觉换 `qwen3-vl:2b`（1.9GB，换页更快） | 思考型模型，需 `/no_think`（代码已自动处理） |
| 最优识别 + 零换页 | 视觉保留云端、文字全本地 | 图片链路需要联网 |

另外两项配套改进：**图片编码前等比缩放**（长边默认 1280，`VISION_MAX_SIDE`，不需要缩放时原样发送不重编码）；
**思考型模型自动加 `/no_think`**（`qwen3` / `deepseek-r1` 等，可用 `DISABLE_THINKING=false` 关闭）。

## 8. API 契约（摘要）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat` | multipart：`conversation_id`、`text`、`image?`；返回 SSE 事件流（`vision`/`retrieval`/`token`/`done`） |

## 10. 测试策略

- **框架**：pytest（`tests/`），与现有 Node 文档校验（`test/`）并存，`scripts/test.ps1` 顺序跑两套。
- **打桩**：所有模型调用经 provider 协议注入假实现，单测不依赖网络与 Ollama。
- **真实联调**：`scripts/probe_vision.py` 单独做一次真实探测，结果人工确认，不进入自动化测试。
- **沙箱约束**：禁用 pytest `tmp_path`/`tmpdir` 夹具（其 mkdtemp 会 `chmod 0700`，沙箱令牌无权限访问）；改用 `tests/conftest.py` 中自建的工作区目录夹具。
- **线程约束**：LangGraph 会在自己的工作线程里执行节点，因此对话请求持有的 sqlite 连接必须
  `check_same_thread=False`；本图是线性流程（无并行分支），节点间不会并发访问该连接，配合 WAL 模式安全。
- **覆盖重点**：分块与元数据、FTS5 与向量召回、RRF 融合与阈值、未命中兜底、多轮记忆、工单结构化校验与非法输出兜底、状态流转合法性。

## 11. 观测与日志

## 12. 前端设计

### 12.1 页面与路由

| 页面 | 路径 | 说明 |
|---|---|---|
| 客户对话页 | `/` | 消息流 + 图片上传 + 「本轮依据」折叠 + 右栏工单草稿实时预览；支持深链 `/?conv=<会话ID>` |
| 人工客服工单台 | `/admin` | 状态 Tab + 搜索 + 列表 + 详情抽屉（字段编辑 / 资料来源 / 处理历史 / 底部固定流转栏）；支持深链 `/admin?ticket=<工单ID>` |
| 前端自检页 | `/static/selftest.html` | 不打开开发者工具即可确认「浏览器 ↔ 后端 ↔ 模型」链路：健康状态 → 知识库 → 真实 SSE 流式对话（事件序列 + 首包耗时）→ 工单接口 |

### 12.2 脚本分工与事件流映射

| 文件 | 职责 |
|---|---|
| `js/api.js` | 所有网络调用；SSE 用 `fetch` + `ReadableStream` 手动解析（对话是 POST multipart，`EventSource` 只支持 GET） |
| `js/ui.js` | DOM 构造、时间格式化、状态/紧急程度渲染、依据折叠块、轻提示、轻量富文本 |
| `js/chat.js` | 对话页：发送 → 事件流处理 → 流式渲染 → 工单草稿 → 依据展示 → 结束会话 → 历史会话抽屉 |
| `js/admin.js` | 工单台：列表/筛选/统计 → 详情抽屉 → 字段编辑 → 状态流转 → CSV 导出 |
| `js/selftest.js` | 自检页 |

SSE 事件到界面的映射（`app/api/chat.py` → `js/chat.js`）：

| 事件 | 界面动作 |
|---|---|
| `meta` | 记录会话 ID（写入 localStorage，刷新后自动恢复）、更新标题 |
| `stage` | 在回答气泡内显示「正在识别图片 / 正在检索资料…」 |
| `vision` | 顶部提示条展示图片识别结论；失败则提示将按文字处理 |
| `retrieval` | 缓存支撑片段，供 `done` 时渲染「本轮依据」 |
| `token` | 逐段追加到回答气泡（首次收到时清掉阶段提示） |
| `draft` | 更新右栏工单草稿与完整度进度条 |
| `done` | 渲染引用块、元信息（通道/命中/降级），并校准最终回答 |
| `error` | 气泡内以错误样式显示原因 |

### 12.3 前端约定

1. **防 XSS**：所有来自后端或模型的文本一律通过 `textContent` / DOM 节点写入，禁止 `innerHTML` 拼接；
   回答正文的 Markdown 也只做「`**加粗**`、`- 列表`、换行」三类结构化渲染（`UI.richText`）。
   `test/project.test.js` 有专门断言守着这条约定。
2. **状态与权限**：状态点、紧急徽标、可用流转按钮都由统一的状态表驱动；前端只渲染合法按钮，
   最终合法性仍由后端裁决（非法流转返回 400 并在页面提示）。
3. **`hidden` 属性**：抽屉与遮罩用 `hidden` 控制显隐，因此全局有一条
   `[hidden] { display: none !important }` 兜底（否则会被组件自身的 `display: flex` 覆盖）。
4. **缓存**：静态资源由 `StaticFiles` 提供并带 ETag/Last-Modified，普通刷新即可拿到最新版本。
