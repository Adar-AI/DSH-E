# 多模态企业智能客服系统 · 需求规格说明书

| 项目 | 内容 |
|---|---|
| 版本 | v1.0（已确认） |
| 日期 | 2026-10-12 |
| 形态 | 单机本地运行的 Web 应用（个人项目） |
| 目标用户 | 中小企业售后场景：终端客户 + 人工客服 |
| 技术基线 | FastAPI + LangGraph + SQLite(FTS5/sqlite-vec) + 本地 BGE-M3 + Ollama + 多模态大模型 |

## 1. 项目背景与定位

模拟中小企业售后场景：客户咨询产品问题，**既有文字提问，也会上传故障截图 / 实物照片**。系统需要像一名懂内部资料的售后工程师一样：先看懂图文，再**只依据企业内部资料**给出售后方案，最后把这次沟通沉淀成结构化工单，供人工客服跟进。

核心定位三条：

1. **私域知识优先**——答案必须来自企业自己的 PDF/MD 资料，不依赖大模型原生知识，从机制上压低幻觉；
2. **多模态**——报错截图、实物照片与文字描述一并理解；
3. **闭环归档**——对话结束自动产出结构化工单并本地落库。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 知识库 | 企业内部 PDF/MD 资料经解析、分块、向量化后存入本地数据库的集合 |
| 分块（chunk） | 知识库的最小检索单元，携带来源文档、章节、页码 |
| RAG | 检索增强生成：先检索资料片段，再让模型基于片段作答 |
| 工单（ticket） | 一次售后诉求的结构化归档记录 |
| 兜底话术 | 检索未命中时明确告知「内部资料未收录」并建议转人工的回应 |
| 降级 | 外部模型不可用时自动切换到备用通道或退化为纯关键词检索 |

## 3. 角色与场景

### 3.1 角色

| 角色 | 入口 | 主要行为 |
|---|---|---|
| 客户 | 对话页 `index.html` | 文字提问、上传截图/照片、连续多轮追问、结束会话 |
| 人工客服 | 工单台 `admin.html` | 筛选/查看工单、流转状态、导出跟进清单 |
| 管理员 | 知识库管理页 | 上传/删除资料、重建索引、查看分块情况 |

### 3.2 主流程

1. 客户在对话页描述问题，可同时附 1 张图片（报错截图或实物照片）；
2. 系统识别图片内容，产出结构化故障描述（报错码、界面位置、实物损坏情况）；
3. 与文字描述合并为检索查询，做混合检索（关键词 + 向量）召回内部资料片段；
4. 命中足够相关片段时，生成售后方案，**每条结论附来源（文档名 · 页码）**；
5. 每轮对话后台增量抽取工单草稿字段，右侧栏实时可见；
6. 客户点「结束会话」，系统定稿工单、校验字段、落库并返回工单号；
7. 人工客服在工单台按状态/关键字筛选，查看详情、流转状态、导出。

### 3.3 异常流程

| 异常 | 系统行为 |
|---|---|
| 知识库未收录该问题 | 走兜底话术，明确说明未收录并建议转人工，**不得编造** |
| 未上传图片但问题依赖图片 | 主动引导客户补充文字描述或重新上传清晰图片 |
| 图片无法识别（模糊/无关） | 说明识别失败原因，降级为纯文字链路继续对话 |
| 本地对话模型未启动 | 自动切换到备用对话通道，页面提示当前使用通道 |
| 向量模型不可用 | 检索退化为纯关键词模式，页面提示检索模式 |
| 模型返回非法 JSON（工单抽取） | 重试一次；仍失败则该字段留空并标记「需人工补录」，不阻塞落库 |

## 4. 功能需求

| 编号 | 模块 | 需求描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| F1 | 多轮对话 | 一次会话内保留上下文，支持连续追问；刷新页面不丢会话 | P0 | 同一会话第 3 轮能正确引用第 1 轮的「产品型号」等信息 |
| F2 | 多模态输入 | 同一轮可提交「文字 + 1 张图片」；图片本地留档并在气泡中回显 | P0 | 上传后数据库有记录、`data/uploads/` 有文件、页面能看到缩略图 |
| F3 | 图片理解 | 把图片转为结构化文字（报错码/界面位置/损坏描述），与文字合并为查询 | P0 | 上传含报错码的截图，抽取结果包含该报错码 |
| F4 | 知识库入库 | 页面上传 PDF/MD；解析→分块→抽取元数据（文档名/章节/页码）→写库 | P0 | 上传 1 份 PDF 后分块数与页数合理，检索能召回 |
| F5 | 检索 RAG | 混合检索（FTS5 关键词 + 向量，RRF 融合）取 Top-K；低于阈值走兜底 | P0 | 命中用例有来源引用；未命中用例输出兜底话术 |
| F6 | 回答生成 | 输出「判断依据 / 处理步骤 / 是否在保 / 后续建议」，附来源引用 | P0 | 回答中每条结论都能对应到检索片段 |
| F7 | 工单生成 | 会话结束提取客户诉求、产品型号、故障现象、报错信息、已尝试操作、紧急程度、建议方案、来源引用，结构化后落库并分配工单号 | P0 | 结束会话后 `tickets` 有记录且字段填充率 ≥ 80% |
| F8 | 工单后台 | 列表（状态/关键字筛选）、详情、状态流转（待处理→处理中→已解决→已关闭）、导出 CSV | P1 | 状态流转有历史事件记录；导出的 CSV 可被 Excel 打开 |
| F9 | 会话管理 | 会话列表、历史消息查看、删除 | P1 | 刷新/重启服务后历史会话仍在 |
| F10 | 知识库管理 | 文档列表、上传、删除、重建索引、显示分块数 | P1 | 删除文档后其分块与向量同步清除，检索不再召回 |
| F11 | 可观测 | 每轮可展开查看「本轮依据」片段（文档名、页码、相似度分数） | P1 | 页面能展开看到 3 条以内依据及分数 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 语言 | 界面与回答均为中文 |
| 视觉 | 淡蓝色系、简洁直观（见第 7 节） |
| 数据 | 全部本地：`data/app.db` + `data/uploads/` + `data/docs/`，不依赖云存储 |
| 启动 | 一条命令启动（`uvicorn`），浏览器访问 `http://127.0.0.1:8000` |
| 依赖 | 复用本机已有 Python 环境；新增依赖仅 pytest 与 sentence-transformers |
| 性能 | 单轮文字问答首字响应 ≤ 8s（本地模型）；知识库 100 页规模检索 ≤ 1s |
| 健壮性 | 任一外部模型不可用时必须降级或明确报错，不得 500 崩溃 |
| 可测试 | 全部核心逻辑可离线单测（模型调用可打桩），沙箱内可跑 |
| 安全 | API 密钥只从环境变量/`.env` 读取，日志与页面脱敏，不入 Git |

## 6. 数据需求

| 数据 | 位置 | 是否入 Git |
|---|---|---|
| 业务库（会话/消息/工单/知识库） | `data/app.db`（SQLite + sqlite-vec） | 否 |
| 客户上传图片 | `data/uploads/` | 否 |
| 企业资料原文 | `data/docs/` | 模拟演示资料入库；真实文档不入库 |
| 密钥配置 | `.env`（已被 `.gitignore` 覆盖） | 否 |

## 8. 反幻觉与合规约束

1. **阈值兜底**：检索相关度低于阈值时一律走兜底话术，禁止凭模型记忆作答；
2. **提示词强约束**：系统提示明确「只能依据给定资料片段回答，资料中没有就直说没有」；
3. **引用可核查**：每条结论附来源（文档名 · 页码 · 片段序号），页面可展开原文；
4. **结构化校验**：工单字段经 Pydantic 校验，非法输出不落库或标记待人工补录；
5. **密钥保密**：密钥不出现在源码、日志、页面、Git 历史中；页面仅显示后 4 位。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 多模态网关模型名不确定 | 图片理解不可用 | 先用探测脚本列出可用模型，失败即回退标准视觉模型并回报确认 |
| 本地对话模型未下载/未启动 | 对话不可用 | 统一 provider 层自动切换备用通道，页面提示 |
| 6GB 显存不足 | 推理变慢或 OOM | 嵌入模型默认 CPU 推理，对话模型独占显存，支持切 ONNX |
| 沙箱令牌对 `chmod 0700` 临时目录无权限 | pip/test 临时目录类工具失败 | 依赖安装走一次性提权；测试禁用 `tmp_path` 等临时目录夹具，改用工作区内自建目录 |
| 密钥泄露 | 账号风险 | 只读 `.env`、日志脱敏、页面仅显后 4 位；演示后建议轮换密钥 |

## 11. 非目标（本期不做）

- 不做多租户、账号体系与权限管理（单机单人使用，按浏览器会话 ID 隔离）；
- 不做工单外部系统对接（钉钉/企业微信/邮件通知）；
- 不做语音、视频输入，仅图片 + 文字；
- 不做分布式部署与容器化；
- 不做模型微调，仅做提示词与检索工程。
